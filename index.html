Architecture

One system, four clients

Exifora as it runs today. Every box is something I designed, built and operate. The travelling lights are the path a photo takes from a phone to a jury.

Clients share one codebase

Compose Multiplatform ships native Android and iOS; Swift is only 13 files of interop. Web is a separate Next.js app on the same API.

Business rules live server-side

Auth, quotas, payments and jury logic are Go usecases over parameterized SQL. Clients render; they do not decide.

Uploads never block the API

Phones and browsers PUT straight to R2 with short-lived presigned URLs. The API only ever sees metadata and EXIF.

Recoverable by design

Continuous WAL archiving to R2 and a rehearsed disaster-recovery runbook. Releases are tag-driven to three stores.

/ route

By cost and stakes

Opus where the output is public or high-stakes, Haiku for volume, Batches for bulk. Model choice is an environment variable, not a rewrite.

/ ground

Prompt grounded, output guarded

Personas per category, EXIF and theme context in every call, and an explicit rule to describe only what is unmistakably visible.

Movie React Native

source on GitHub · 2025

A React Native and Expo reference app, written to show how I structure a cross-platform TypeScript codebase: Expo Router file-based navigation, a tabbed movie list and detail flow, skeleton loaders, haptic tabs and a Reanimated favourite animation.

The interesting part is underneath. A hand-written fetch pipeline adds an AbortController timeout, retries, a 401 refresh-token round trip and normalized errors surfaced as toasts. Every response is parsed through a Zod schema before it becomes a domain model, so the UI never sees an unvalidated payload. Zustand stores persist favourites and tokens to AsyncStorage behind an explicit hydrate step, and 26 Jest tests across six suites cover the network layer and every store.
